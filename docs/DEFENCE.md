# DEFENCE.md — The Architectural Defence
**Team Beacon · Phase 2: The Continuous Mesh & The Ratchet Effect**

This is the live-defence companion to `docs/BLUEPRINT.md`. Structure: the story in one paragraph, the
three dilemmas as claim → mechanism → proof-in-demo → known limit, business impact, and a Q&A bank.
Everyone presenting should be able to say the bolded lines verbatim.

---

## 1. The story in one paragraph

Phase 1 gave heterogeneous agents a shared, typed language and a way to reach signed contracts with
no coordinator — *contracts, not conversations*. Phase 2 gives the mesh a memory with the same
discipline — *evidence, not claims*. An insight is a **capsule**: a typed decision rule carrying a
falsifiable claim, the seeds to replay it, its scope, and its provenance. Before a capsule enters
collective memory it must survive execution — counterfactual replay by a sortition jury on scenarios
its author never saw — and pass the **Pawl**, the autonomous guardrail that makes the ratchet
mechanical: **a ratchet without a pawl spins backward; ours structurally cannot ratchet toward less
safety.** Once admitted, memory is defended in depth: shadow staging, Sentinel probes (memory has CI),
provenance bisect, and **Excision** — surgical removal of a poisoned capsule and its descendants
without ever resetting collective memory. Consistency is layered: **storage is eventually consistent,
meaning is scoped, decisions are deterministic** — the same pure arbitration function from Phase 1
resolves fabric conflicts on every replica identically, so there is no split-brain behavior even when
stores momentarily diverge.

## 2. Dilemma A — Innovation vs. Hallucination

**Claim:** *We never validate what an agent says; we validate what its capsule does — twice, with and
without it, on scenarios the author has never seen. A hallucination can survive a conversation; it
cannot survive execution.*

Mechanism (BLUEPRINT §5): Pawl static checks → hash-sortition jury of 3 (author excluded, committee
verifiable by anyone, unpredictable before the capsule's own hash exists) → counterfactual replay on
the author's seeds (same seed, with/without the capsule — the delta is **causal by construction**) →
author-blind held-out scenarios generated by each juror → invariant/conformance checks in every
episode → 2-of-3 signed quorum certificate → shadow staging on 10 live tasks before ACTIVE. The
certificate travels with the capsule: **the proof of verification propagates with the insight.**

Proof in demo: validation panel shows the with/without deltas per juror; a fabricated-claim capsule
and an overfit capsule die at the correct stages in `tests/test_dilemma_a.py`, live-runnable.

Known limit (own it before asked): quorum replay is not BFT — a colluding jury majority could admit a
lie. Backstop is Sentinels + Excision + juror reputation slashing; the adversary model is stated in
BLUEPRINT §13. Also, held-out scenarios come from the simulator; in production the equivalent is
shadow mode on real traffic — the seam is explicit.

**Why this consensus design:** validation is a *replay* problem, not an *ordering* problem. We need
"did k independent parties reproduce the effect," not "what is the global order of writes."

## 3. Dilemma B — Drift & Poisoning

**Claim:** *Admission control is a border wall; a fabric needs an immune system. We assume some poison
gets in and make its removal surgical, not amnesiac.*

Mechanism (BLUEPRINT §6), in layers:
1. **Border — the Pawl.** Headline rule, **ratchet monotonicity**: capsules may tighten
   SAFETY/COMPLIANCE bounds, never loosen them — loosening requires a signed human operator token.
   The safety ratchet turns one way *by construction, not by review*. Plus: bounded contexts (blast
   radius), falsifiable-claim schema, identity, reputation-scaled rate limits, auto-isolation below
   reputation 0.3.
2. **Structure.** Adoption-as-prior + local invariant enforcement: a poisoned ACTIVE capsule can
   degrade optimality inside one context; it can never flip an invariant anywhere.
3. **Time.** Shadow staging: a new capsule's first 10 applications influence nothing.
4. **Immune system.** Sentinel probes replay a pinned golden suite against the current ACTIVE set
   every 60 sim-seconds and compare *all* KPIs — **memory has CI**. A regression triggers provenance
   **bisect** (*we bisect memory the way engineers bisect code*) → **Excision**: tombstone the
   culprit, transitively quarantine descendants for re-validation without the poisoned evidence,
   slash author and approving-juror reputation. Everything else is untouched.

Proof in demo: the blatant poison (`allowlist_subnet` in a SAFETY context) is blocked live by the
Pawl with its reason string on screen. The subtle poison — which *honestly improves its claimed
metric* but degrades an off-claim KPI — passes admission, is caught by a Sentinel within a probe
period, bisected, excised. Capsule count goes **12 → 10, not 12 → 0**: collective memory is never
reset. That is the PS requirement answered literally and visibly.

Why the subtle-poison demo is the honest one: it concedes admission can't catch everything (true of
any admission system) and shows the recovery machinery — which is the actual hard part of the
dilemma. Judges distrust systems whose demos only show attacks they were built to catch.

## 4. Dilemma C — Consistency at Scale

**Claim:** *Storage is eventually consistent. Meaning is scoped. Decisions are deterministic.*

Mechanism (BLUEPRINT §7): the store is a CRDT OR-set of content-addressed, signed capsules replicated
by gossip anti-entropy — concurrent adds commute, partitions never block, heal is set union; there is
no storage conflict *by construction*. Two capsules with disjoint contexts are two truths, not a
conflict — which is exactly the PS's "conflicting fixes valid in different contexts." When contexts
genuinely overlap on a live task, every replica calls the same pure `arbitrate()` from Phase 1
(priority class → confidence-weighted → hash tie-break): same replicated inputs + pure function =
identical decision everywhere, **no split-brain behavior even while stores momentarily diverge**.
Persistent overlap triggers **Refine**: *a conflict is an underspecified context* — split the
predicate along the dimension where the two capsules' evidence separates, keep both truths, sharpen
the map. Partition-formed quorum certs are provisional (recorded `partition_view`); minority-island
promotions demote and re-jury on heal — preserved, never silently authoritative.

**CAP stance:** AP for memory, and we can afford it because **safety was moved out of the consistency
layer entirely** — invariants are enforced locally by every agent, so divergence degrades optimality,
never safety. *Slow, never unguarded* (Phase 1's principle, kept).

Chosen model, named for the rubric: **scoped consistency** (per-context), with CRDT eventual
consistency for storage and deterministic-function consistency for decisions. Trade-offs: gave up
global total order and cross-context atomicity; kept the ledger's *useful* properties (append-only,
signed, content-addressed, hash-linked provenance = fully auditable) without its liveness cost.

## 5. Business impact — why Cisco should care

Frame: **the marginal cost of a solved problem should be zero across the fleet.** Today every site,
shift, and session pays full discovery cost for the same incident class; when the session ends, the
learning evaporates (the PS's "transient memory"). The fabric turns operational learning from an
ephemeral side effect into a **versioned, audited, revocable asset**.

- **MTTR and toil.** First site pays discovery cost once; every subsequent site pays reuse cost. In
  the demo's controlled A/B (same seeded incident storm, fabric on vs off), cumulative cost drops
  ~40–50% with ~40% incident recurrence — and recurrence in real enterprise ops (config drift, cert
  expiries, scanning waves, seasonal DDoS) is the norm, at thousands-of-sites scale. Fewer repeat
  escalations, fewer 3 a.m. pages for problems the network already solved.
- **Governable autonomy — the adoption unlock.** Enterprises don't fear automation; they fear
  *unauditable* automation. Here every automated action cites a capsule; every capsule carries its
  evidence, its jury certificate, its provenance, and a revocation path. Compliance teams review and
  approve *capsules* (small, typed diffs) instead of babysitting individual actions — governance
  moves from per-incident to per-insight. The shadow → canary → active lifecycle is exactly how
  enterprises already adopt risky changes, so the trust model is familiar.
- **The Pawl as a sellable guarantee.** "The system can autonomously get stricter, and can only get
  looser with a signed human decision" is a one-sentence security posture an operator, an auditor,
  and a CISO all understand.
- **Institutional memory vs. churn.** Tribal knowledge (the senior engineer who remembers the 2024
  incident) becomes a queryable, provenance-tracked artifact that survives staff turnover, agent
  restarts, and vendor model swaps — the fabric is model-agnostic because capsules are typed
  behavior, not prompts.
- **Network effect, honestly stated.** Value scales with sites × incident recurrence; the fabric is
  worth little to one site and compounding to a fleet — which is precisely the customer shape of a
  networking company. (And per-capsule, not per-agent-pair: propagation is O(capsules), no N².)
- Honesty rider (say it before asked): the economics in the demo are simulated; the claim is the
  controlled *shape* — same seed, fabric on vs off — not the absolute numbers.

**People impact, one breath:** humans stop being the network's only memory. They move from
firefighting every recurrence to curating what the network is allowed to remember — and they remain
the only authority that can loosen a safety bound.

## 7. Judge Q&A bank

**Q1. Why not a blockchain/ledger? The PS suggests one.**
The PS says "ledger, cache, *or equivalent*." A ledger's primitive is total order; our problem's
primitive is verified content with partial, per-context order. Total order costs liveness under
partition and buys nothing here — capsule validity comes from replay and signatures, not position in
a chain. We kept the ledger properties that matter — append-only, signed, content-addressed,
hash-linked provenance, tombstoned deletes — so the fabric is fully auditable, and dropped the
consensus bottleneck.

**Q2. What if jurors collude or are compromised?**
Sortition is seeded by the capsule's own hash — the committee can't be predicted before the capsule
exists or chosen by its author, and anyone can verify the committee was correct. A colluding majority
of a 3-jury could still admit a lie: that's inside our stated adversary model ("few rogue agents,"
BLUEPRINT §13), and the backstop is Sentinels + bisect + Excision + juror slashing — jurors stake
reputation on every signature. Raising JURY_K trades latency for collusion resistance; it's one
constant.

**Q3. Can an author game the held-out set?**
No — held-out scenarios are generated by each juror from the declared context class's parameter
space using the juror's own seed stream. The author never sees them, and declaring a narrower context
to dodge hard cases also narrows where the capsule is ever applied. Gaming the context shrinks your
own blast radius.

**Q4. Your simulator validates the capsule — what about reality (sim-to-real)?**
Stated openly: episodes are stylized. The production seam is explicit — conformance tests are the
contract with reality, and shadow staging would run on real traffic before ACTIVE. The architecture
(replay, jury, certs, excision) is transport- and environment-agnostic; the simulator is the demo's
stand-in for the environment, not a hidden assumption.

**Q5. How does memory not grow forever / go stale?**
TTLs with confidence decay; SUPERSEDED links when a better capsule wins the same context; usage-based
expiry (EXPIRED capsules stay readable for audit, stop applying). The fabric forgets gracefully,
never abruptly — and never by fiat, always by lifecycle.

**Q6. Privacy — sites shipping their data into shared memory?**
Capsules carry typed policy deltas over registry dimensions plus seeds and digests — never raw
traffic, prompts, or model internals. This is Phase 1's minimum-disclosure discipline carried
forward; the fabric shares *what to do*, not *what was seen*.

**Q7. Why five agents when Phase 1 was two?**
Phase 1's problem was bilateral (a handshake). Phase 2's claims — propagation, quorum validation,
partition/heal, sortition excluding the author — are only demonstrable with N>3. Five is the smallest
mesh where a 3-jury excludes the author with room, and a partition leaves a viable majority side.

**Q8. Two agents discover conflicting fixes — walk me through it.**
If contexts are disjoint: two truths, both ACTIVE, no protocol needed. If they overlap: every node
resolves a live task with the same pure arbitrate() — identical answer everywhere, no coordinator.
If the overlap persists: Refine splits the predicate along the dimension where their evidence
separates; both survive, scoped. We never last-writer-wins a valid truth out of existence.

**Q9. What exactly is a "breakthrough"? Sounds subjective.**
Operationally defined or it doesn't exist: a typed decision rule with a measured causal delta ≥ 15%
median on author-blind scenarios of its declared class, zero invariant violations, quorum-certified.
No vibes anywhere in the pipeline.

**Q10. Why isn't the memory just fine-tuning / model weights?**
Weight updates are uninspectable, unattributable, and unrevocable — you cannot excise one insight
from a fine-tune, and you cannot show an auditor which gradient caused which behavior. Capsules are
inspectable, attributable, individually revocable, and model-agnostic: swap the strategist model,
keep the fleet's memory.

**Q11. Isn't this just RAG?**
RAG retrieves text for a model to *read*; the fabric stores validated, typed, executable policy with
a lifecycle, a guardrail, and a revocation path. Nothing retrieved here is prose, and nothing applied
here skips the invariant check. Closest true relatives: package registries with signed artifacts, and
CI/CD for config — memory treated as code.

**Q12. What happens during a partition — really?**
Both islands keep working and keep learning (AP). Certs formed on a minority island are marked by
their partition_view; on heal the stores union (CRDT), minority promotions demote to CANDIDATE and
re-jury mesh-wide, overlaps re-arbitrate deterministically, persistent ones Refine. Shown live in the
chaos act. Worst case is temporary sub-optimality on one island — never divergent *safety*, because
invariants are local.

**Q13. The rogue agent is yours — isn't the attack strawmanned?**
The blatant attack is the strawman and we treat it as one (the Pawl blocks it — border works). The
demo's real attack is the subtle one: a capsule that *honestly wins its claimed metric* and regresses
an off-claim KPI. It defeats admission by design, and the system still recovers. We attack our own
weakest layer on stage.

**Q14. Where do humans sit?**
Two places, deliberately: loosening any SAFETY/COMPLIANCE bound requires a signed operator token
(the pawl's one-way clause), and Excision reports are human-readable audit artifacts. Humans curate
memory and own de-escalation; the fabric owns recurrence.

**Q15. What's Phase-1 continuity, concretely?**
The registry (now with incident dimensions), the invariants, the priority lattice, signed identities,
the audit chain, and — verbatim — the arbitrate() function: the same code that settled two-agent
contract conflicts settles N-agent memory conflicts. Capsules themselves were specified in our
Phase 1 submission's ideation as the designed Phase-2 seam.
