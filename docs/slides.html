Cognition Fabric: a shared memory that agents have to earn

Soumyakanta Panda · Balla Pranava Chaitanya · Srujan K R

The problem we solve

  • A mesh of autonomous agents solves incidents all day, then forgets. Every site pays full discovery cost for the same problem, and a restart wipes the learning.
  • Naively sharing what agents "learned" is worse: hallucinated fixes spread, poisoned knowledge persists, and two sites can hold conflicting fixes that are both valid in their own contexts.
  • Phase 2 asks for a fabric that captures a local breakthrough, verifies it autonomously before acceptance, propagates it fast, and shows measurable reuse. Poison removal must work without resetting collective memory.
Phase 1 was contracts, not conversations. Phase 2 is evidence, not claims: nothing enters collective memory because an agent said so. It enters because its claim survived re-execution.

Methodology

  • An insight is a capsule: a typed decision rule carrying a falsifiable claim, the seeds to replay it, its scope, and its provenance. Never free text, so machines can verify it.
  • Validation is execution. A jury of 3 agents, picked by the capsule's own hash so nobody can choose the committee, replays the claim with and without the capsule on scenarios the author never saw.
  • The guardrail (the Pawl) is structural: capsules may tighten safety bounds, never loosen them. Loosening needs a signed human token.
  • We assume some poison still gets in. Sentinel probes re-test active memory on a pinned golden suite, a bisect finds the culprit in log time, and excision removes exactly the poisoned subtree.
  • Consistency in three layers: storage is a CRDT that merges without conflicts, meaning is scoped per context, and decisions come from one pure function that gives the same answer on every node.

The three dilemmas are answered as running code

A. Innovation vs. hallucination

A fabricated claim dies at counterfactual replay. A cherry-picked claim dies on author-blind scenarios. A true but unsafe gain dies at the invariant check. Each is a test that runs in front of you: tests/test_dilemma_a.py

B. Drift and poisoning

A subtle poison that honestly improves its claimed metric passes admission, then a sentinel catches the damage on a metric nobody claimed. Bisect, excise, slash reputation. Memory goes 12 to 10, never to zero. tests/test_dilemma_b.py

C. Consistency at scale

A partition lets two islands learn different valid fixes. Heal is a set union, every node arbitrates identically, and a Refine split lets both truths survive with sharper scopes. tests/test_dilemma_c.py

110 tests pass in under a second, including a determinism test: both demos produce byte-identical output on every run, chaos included.

Tools, technologies, and implementation highlights

Small toolset, production-grade patterns, measured results

Tools and technologies

Python 3.11 with asyncio, pydantic for typed schemas, rich for the dashboard, pytest, uv for the environment. Everything else is the standard library: hashlib, hmac, json, seeded random. No database, no network calls, no blockchain library. Installs in seconds and runs fully offline.

What you are about to see

Demo 1: the ratchet (about 40 s)

  • Fabric off: two sites pay full price for the same incident, a crash loses everything.
  • Fabric on: site-a authors a capsule, a hash-picked jury accepts it, promotion is derived across the mesh, site-c reuses it at half the cost.
  • site-d crashes again and restarts with memory. Same crash, different outcome.

Demo 2: chaos (about 100 s)

  • A blatant poison is blocked live, reason on screen.
  • A subtle poison honestly passes admission, a sentinel catches it on a metric nobody claimed, bisect finds it in 4 probes, excision takes memory from 12 to 10.
  • A partition splits the mesh, both islands keep learning, heal converges every node on the identical decision, and a Refine split keeps both truths.
